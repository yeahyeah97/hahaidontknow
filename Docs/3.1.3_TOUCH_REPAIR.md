# Milazy 3.1.3 touch repair

Audit of 3.1.2:
- KeyCanvas selected the nearest key for outer middle-row points, then returned
  a UIButton whose tracking bounds could reject that very point.
- Independent UIButton tracking did not give us ownership of every overlapping
  contact, including two contacts on one key.
- Probability scoring could choose a neighbor within a visible cap, and normalized
  width could bias gap choices toward wide Shift/Return keys.
- Integration tests invoked actions directly; they bypassed the native touch route.

Changes preserve all reference frames and the existing IT/EN correction corpus.
KeyCanvas owns public UIKit multi-touch events and tracks each contact separately.
It resolves and commits once at touch-down, before deferred visual feedback.
Dragging/releasing/canceling does not add or exchange already-inserted characters.
Page changes and view disappearance cancel contacts and pending Delete holds.
Delete repeat uses the same contact lifecycle rather than a competing recognizer.
Painted keycaps own their taps; probabilistic learning resolves invisible gaps.
Gap scoring uses distance to cap boundaries so wide special keys do not dominate.
Touch model reads use a nonblocking lock attempt and fall back to the neutral model
when learning is publishing, instead of waiting on the background worker.

Validation includes the existing immediate Space/undo/capitalization tests through
the canvas route, overlapping contact/duplicate begin/drag/cancellation checks,
every letter cap corner, outer row edges, gaps, and Delete repeat cancellation.
An additional simulator application exercises real UIKit coordinate taps and drag
events through the production keyboard controller. It is not included in the IPA.

Public API references:
- https://developer.apple.com/documentation/uikit/uiview/ismultipletouchenabled
- https://developer.apple.com/documentation/uikit/uiresponder/touchesbegan(_:with:)

These checks cannot establish native iOS 27 equivalence or actual two-thumb timing
in WhatsApp on the phone. CI currently uses Xcode 16.4 and the iOS 18.5 simulator.
